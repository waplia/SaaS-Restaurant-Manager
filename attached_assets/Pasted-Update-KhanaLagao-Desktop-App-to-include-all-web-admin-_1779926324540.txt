====================================================
6. OFFLINE-FIRST DESKTOP SUPPORT
====================================================

Desktop app should work offline where possible.

Offline allowed:
- Login only if user/session was previously synced.
- View cached menu/categories/tables/customers.
- Create POS cart.
- Hold bill locally.
- Create offline order draft.
- Print KOT/bill locally if printer available.
- Save failed print jobs.
- Cash payment offline.
- Add expense draft.
- Add stock adjustment draft if permission allows.
- Continue shift locally.

Offline not allowed:
- First-time login.
- Online payments/terminal verification.
- SMS/WhatsApp/email sending.
- Provider configuration changes.
- Cloud-only AI actions.
- Live QR order acceptance unless already cached/synced.

When online returns:
- Sync offline orders.
- Sync held bills.
- Sync shift actions.
- Sync cash payments.
- Sync print status.
- Sync expenses/purchases/stock actions.
- Sync audit logs.
- Retry failed jobs.
- Show conflicts.

Conflict rules:
- Preserve bill snapshot for offline orders.
- Keep offline item price used at billing time.
- Server assigns final internal order ID if needed.
- If stock changed, sync order and flag stock conflict.
- If customer changed, merge safely or show conflict.
- Never duplicate orders during retry.
- Use idempotency keys for every offline action.
