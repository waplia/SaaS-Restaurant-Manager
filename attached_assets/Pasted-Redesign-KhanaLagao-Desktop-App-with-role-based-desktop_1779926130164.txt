Redesign KhanaLagao Desktop App with role-based desktop modes and offline sync.

Current requirement:
Desktop app should not show Back Office as a normal module to every user. The desktop app should open different UI based on logged-in user role, same like mobile app role-based flow.

Cashier should see only POS.
Admin/Manager should see full manager/admin office with restaurant setup, menu, stock, payments, reports, customers, suppliers, expenses, logs, database, etc.
Inventory staff should see stock/purchase/supplier features.
Accountant should see finance/reports/payments/bank reconciliation.
Owner should see all features.

Important:
- Do not show admin/back-office features to cashier unless permission allowed.
- Role-based UI must work after login.
- Use same backend data as web admin.
- Desktop app should work offline where possible and sync when online.
- No mock data.
- No dead buttons.
- No raw ID inputs.
- No infinite loading.

====================================================
1. ROLE-BASED DESKTOP ENTRY FLOW
====================================================

After login:
1. Detect user role.
2. Detect assigned outlet/branch.
3. Detect permissions.
4. Open correct desktop mode.

Role modes:

A. Cashier Mode
- Opens directly to POS.
- Shows only:
  POS
  Orders
  Payments
  Shift
  Hardware if allowed
  Logout

B. Manager/Admin Mode
- Opens Manager Office dashboard.
- Can access:
  POS
  Orders
  Tables
  Customers
  Menu
  Inventory
  Purchase
  Suppliers
  Payments
  Expenses
  Reports
  Hardware
  Settings
  Logs if allowed

C. Owner Mode
- Full access to everything.

D. Inventory Staff Mode
- Opens Inventory dashboard.
- Shows:
  Raw Materials
  Menu Item Stock
  Warehouse
  Stock Transfer/Issue
  Purchase
  Supplier
  Wastage
  Low Stock
  Inventory Reports

E. Accountant Mode
- Opens Finance dashboard.
- Shows:
  Payments
  Voucher
  Expense Type
  Expense
  Cards
  Wallet
  Bank Reconciliation
  Accounting Reports
  POS Report
  Work Period Report
  Settlements

F. Delivery Staff Mode
- Opens Delivery dashboard if desktop access allowed.
- Shows delivery orders and COD settlement only.

If user has multiple roles:
Show role switcher after login.

If user has multiple outlets:
Show outlet selector.

====================================================
4. OFFLINE-FIRST DESKTOP SUPPORT
====================================================

Add offline support for desktop app.

Offline should support:

Cashier/POS offline:
- Create cart
- Add items
- Hold bill
- Print local bill/KOT if printer available
- Save offline order draft
- Save failed print jobs
- Continue cashier shift locally
- Show offline banner

Offline should NOT allow:
- Online payments
- Payment provider verification
- Cloud sync actions
- SMS/WhatsApp/email sending
- Real-time QR order acceptance unless already synced

When online returns:
- Sync offline orders
- Sync held bills
- Sync print status
- Sync cash shift actions
- Sync expenses/purchases created offline if allowed
- Resolve conflicts

Conflict handling:
- If item price changed while offline, keep original offline bill snapshot.
- If order number conflict, generate final server order number during sync.
- If stock changed, sync order and flag stock conflict if needed.
- Show sync review screen for failed/conflicted items.
