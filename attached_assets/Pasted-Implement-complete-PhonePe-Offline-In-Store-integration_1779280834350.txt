3. PHONEPE X-VERIFY / CHECKSUM IMPLEMENTATION
====================================================

Create backend utility:

phonepeOfflineSigner.ts or phonepeOfflineSigner.js

Functions:
- base64EncodePayload(payload)
- generateEdcSaleXVerify(base64Payload, saltKey, saltIndex)
- generateEdcStatusXVerify(merchantId, transactionId, saltKey, saltIndex)
- verifyCallbackSignature if docs/header available
- buildHeaders(providerConfig, callbackUrl)

EDC Sale X-VERIFY:
SHA256(base64 encoded payload + "/v1/edc/transaction/init" + saltKey) + "###" + saltIndex

EDC Status X-VERIFY:
SHA256("/v1/edc/transaction/{merchantId}/{transactionId}/status" + saltKey) + "###" + saltIndex

Headers for EDC Sale:
Content-Type: application/json
X-VERIFY: generated checksum
X-PROVIDER-ID: optional, only if configured
X-CALLBACK-URL: EDC callback URL

Headers for EDC Status:
Content-Type: application/json
X-VERIFY: generated checksum
X-PROVIDER-ID: optional, only if configured

Important:
- Generate X-VERIFY only on backend.
- Never calculate checksum on frontend.
- Add unit tests for X-VERIFY generation.
- Log only safe metadata, not salt key.

7. EDC SALE REQUEST API IMPLEMENTATION
====================================================

Create backend API:
POST /api/payments/phonepe/edc/sale

Request from POS:
{
  invoiceId,
  orderId,
  terminalId,
  paymentModes: ["CARD", "DQR"],
  integrationMappingType,
  timeoutSeconds
}

Backend should:
1. Authenticate user.
2. Check restaurant/outlet.
3. Check permissions.
4. Check provider configured by Super Admin.
5. Check restaurant plan/payment mode enabled.
6. Load invoice/order.
7. Validate amount > 0.
8. Load PhonePe terminal mapping.
9. Generate unique phonepe_order_id.
10. Generate unique phonepe_transaction_id under 40 chars.
11. For OPEN mode generate 4-8 digit shortOrderId.
12. Build PhonePe payload.
13. Base64 encode payload.
14. Generate X-VERIFY.
15. POST to PhonePe EDC Sale endpoint.
16. Store payment transaction with raw request/response.
17. Return safe result to frontend.

PhonePe EDC Sale payload:
{
  "merchantId": "<merchantId>",
  "storeId": "<storeId>",
  "orderId": "<billing/order id>",
  "terminalId": "<terminalId for ONE_TO_ONE>",
  "shortOrderId": "<4-8 digit code for OPEN only>",
  "transactionId": "<unique transaction id>",
  "amount": <amount in paise>,
  "paymentModes": ["CARD", "DQR"],
  "timeAllowedForHandoverToTerminalSeconds": 60,
  "integrationMappingType": "ONE_TO_ONE"
}

Payload wrapper:
{
  "request": "<base64 encoded payload>"
}

https://mercury-uat.phonepe.com/enterprise-sandbox/v1/edc/transaction/init

8. EDC STATUS CHECK API IMPLEMENTATION
====================================================

Create backend API:
GET /api/payments/phonepe/edc/status/:transactionId

Backend should:
1. Authenticate user.
2. Find payment transaction by transactionId and restaurant scope.
3. Load provider config.
4. Generate X-VERIFY:
SHA256("/v1/edc/transaction/{merchantId}/{transactionId}/status" + saltKey) + "###" + saltIndex
5. POST to PhonePe Status endpoint.
6. Save raw response.
7. If status SUCCESS and amount matches:
   - Mark payment transaction success
   - Mark invoice paid
   - Mark order paid if needed
   - Save referenceNumber
   - Save paymentMode
   - Save paymentInstruments
   - Create payment ledger entry
   - Update cashier closing/report data
   - Trigger payment success notification
8. If PENDING:
   - Keep pending
9. If FAILED or EXPIRED:
   - Update status
   - Do not mark paid
10. Return current status to POS.

Status response fields to handle:
- merchantId
- storeId
- terminalId
- orderId
- transactionId
- referenceNumber
- paymentMode: CARD or DQR
- amount in paise
- status: PENDING, SUCCESS, FAILED, EXPIRED
- responseCode
- paymentInstruments
- timestamp

9. EDC S2S CALLBACK IMPLEMENTATION
====================================================

Create callback endpoint:
POST /api/payments/phonepe/edc/callback

This endpoint must be public but secure.

Callback handling:
1. Store raw callback in phonepe_callbacks.
2. Verify callback authenticity according to PhonePe docs/header if available.
3. Extract merchantId, orderId, transactionId, amount, status, referenceNumber, paymentMode.
4. Find payment transaction.
5. If transaction not found, store callback as unmatched.
6. For safety, call EDC Status Check API to verify final status.
7. If verified SUCCESS and amount matches:
   - Mark payment transaction success
   - Mark invoice paid
   - Mark order paid
   - Save referenceNumber
   - Save paymentMode
   - Save paymentInstruments
   - Create ledger/payment record
   - Update reports
8. If failed/expired:
   - Update status
9. Make callback idempotent:
   - Same callback should not duplicate payment.
   - If already success, ignore duplicate safely.
10. Return HTTP 200 after processing.

Never mark paid without backend verification.
