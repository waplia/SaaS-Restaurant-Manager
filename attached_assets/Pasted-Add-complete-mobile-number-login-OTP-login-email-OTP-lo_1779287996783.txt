Add complete mobile number login, OTP login, email OTP login, restaurant registration, and two-factor authentication support across KhanaLagao web and mobile app.

Current requirement:
KhanaLagao should support login using mobile number on both web and mobile app. It should also support full restaurant registration from the restaurant mobile app. Two-factor authentication should work using OTP through mobile SMS/WhatsApp or email depending on Super Admin configuration.

Important:
- Do not break existing email/password login.
- Do not break Super Admin login.
- Do not break current restaurant admin, staff login, mobile app login, POS, QR menu, or backend.
- Add mobile number login as an additional login method.
- OTP provider configuration must be controlled only by Super Admin.
- Restaurant admin should not manage OTP/SMS/email provider API keys.
- OTP must be secure, expiring, rate-limited, and logged.
- Mobile app and web should use the same backend auth system.
- No mock OTP success.
- No fake login.
- All auth flows must use real database, real OTP generation, real provider if configured.
- If provider is not configured, show proper configuration error.

Feature name:
Mobile Login + OTP Authentication + Restaurant Registration + 2FA

====================================================
1. SUPPORTED AUTH FLOWS
====================================================

Support these login methods:

1. Email + Password
Existing flow should continue working.

2. Mobile Number + OTP
User enters mobile number.
System sends OTP by SMS or WhatsApp based on Super Admin setting.
User verifies OTP.
User logs in.

3. Email + OTP
User enters email.
System sends OTP to email.
User verifies OTP.
User logs in.

4. Password + 2FA OTP
User enters email/mobile + password.
If 2FA enabled, system sends OTP to configured channel.
User verifies OTP.
Then login completes.

5. Mobile App Restaurant Registration
New restaurant owner can register from mobile app.
Registration uses mobile/email OTP verification.
After verification, restaurant workspace is created.

6. Staff Login
Staff can login using:
- Mobile + OTP
- Email + OTP
- Email/mobile + password + optional 2FA
based on restaurant/Super Admin settings.

7. Super Admin Login
Keep Super Admin secure.
Allow existing login.
Optional 2FA for Super Admin using email/mobile OTP if enabled.

====================================================
11. OTP REQUEST API LOGIC
====================================================

POST /api/auth/request-otp

Input:
- identifier_type: mobile/email
- mobile_number
- country_code
- email
- purpose
- channel optional: sms/whatsapp/email

Backend logic:
1. Validate identifier.
2. Check global auth settings.
3. Check purpose allowed.
4. Check rate limits.
5. Check existing account if login purpose.
6. Generate OTP.
7. Hash OTP.
8. Save otp_verifications.
9. Select provider:
   - Super Admin default channel
   - Restaurant preferred channel if allowed
   - Fallback channel if primary fails
10. Send OTP.
11. Save provider message ID/log.
12. Return safe response:
   “OTP sent if account exists.”

For security:
- Do not reveal if account exists for login unless desired.
- For registration, allow new mobile/email.

====================================================
12. VERIFY OTP API LOGIC
====================================================

POST /api/auth/verify-otp

Input:
- identifier
- purpose
- otp
- registration_session_id optional

Backend logic:
1. Find latest pending OTP.
2. Check expiry.
3. Check attempts.
4. Compare hashed OTP.
5. If valid, mark verified.
6. For login:
   - Find user.
   - Check status.
   - Create session/JWT.
   - Return role, restaurant, outlet access.
7. For registration:
   - Mark mobile/email verified in registration session.
8. For 2FA:
   - Complete login challenge.
9. Log success/failure.
