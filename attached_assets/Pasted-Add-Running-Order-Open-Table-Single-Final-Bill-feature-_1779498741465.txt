Add Running Order / Open Table / Single Final Bill feature for dine-in restaurant orders.

Current problem:
When a customer orders again from the same table, the system creates a separate order and separate bill. In real restaurants, customers usually order multiple times during the same sitting, but final bill should be single.

Required behavior:
- For dine-in table orders, create one active running order per occupied table.
- If the same table orders again before final settlement, add new items to the existing active running order instead of creating a separate final bill.
- Print a separate KOT only for newly added items.
- Generate one combined final bill when staff/customer chooses Generate Bill or Settle Bill.

Flow:
1. Customer/staff creates first order for a table.
2. Table status becomes occupied/running.
3. Order status becomes running/open.
4. KOT prints for first items.
5. If more items are added later from same table, append them to the same running order.
6. Print new KOT only for newly added items.
7. Keep all items under the same bill/order session.
8. When customer asks for bill, generate a single bill containing all items from the running order.
9. After payment, close the order and mark table as available.

Add options:
- Add More Items
- View Running Order
- Generate Final Bill
- Settle Bill
- Close Table
- Split Bill optional
- Move Table optional
- Merge Tables optional

Table order logic:
- Each table can have only one active running order at a time.
- If active order exists, new dine-in order should ask:
  “Table already has a running order. Add items to existing bill?”
- Default action should be Add to Existing Bill.
- Do not create a new bill unless staff explicitly chooses New Separate Bill.
- Separate bill option should require manager permission if enabled.

KOT logic:
- Every new item addition should create a new KOT batch.
- KOT should print only newly added items.
- Modified items should print modified KOT.
- Cancelled items should print cancelled KOT.
- Final bill should include all active/non-cancelled items from all KOT batches.

Bill logic:
- Final bill should show all items together.
- It can optionally show order rounds/KOT references.
- Bill should include subtotal, taxes, service charge, discounts, tips, round off, and grand total.
- UPI QR should print on final bill if enabled.
- Do not print UPI QR on KOT.

Important rules:

- Running order should mainly apply to dine-in table orders.
